# DEMO.md — сценарий финальной презентации

Чеклист демонстрации для защиты интенсива. Покрывает SM-1 (рабочий E2E),
SM-3 (устойчивость к некорректным входам), SM-4 (работа с AI: ошибки,
галлюцинации и их исправление), SM-2 (достоверность результатов).

## Подготовка (до презентации)

1. Прод-URL задеплоен на Render, `/api/health` отвечает 200.
2. В Render Environment Variables заполнены `GEMINI_API_KEY` и `LLM_MODEL`.
3. Подготовлены файлы демо:
   - `resume-real.pdf` — настоящее резюме (своё или тестовое с реальными фактами);
   - `resume-broken.pdf` — переименованный .txt или обрезанный PDF;
   - текст-не-вакансия ≥200 символов (например, рецепт блинов);
   - настоящая вакансия с HeadHunter (скопированная в буфер).
4. Открыт `PROMPTS.md` в отдельной вкладке — показать аудитории источник промптов.
5. Резервный план: локальный запуск `npm start` на случай падения прода.

## Сценарий (~7 минут)

### Шаг 1. Happy path (SM-1)

1. Открыть прод-URL, показать trust-line «Мы не добавляем факты…».
2. Загрузить `resume-real.pdf` перетаскиванием.
3. Вставить вакансию с HeadHunter, выбрать тональность «Профессиональная».
4. Нажать «Сгенерировать» — показать стадии процесса.
5. Развернуть превью обоих документов, скачать резюме в PDF и письмо в DOCX.
6. Открыть скачанные файлы — читаемая кириллица, структура, оформление.

### Шаг 2. Устойчивость к некорректным входам (SM-3)

1. **Битый файл:** загрузить `resume-broken.pdf` → показать inline-ошибку
   («Не удалось прочитать файл…»), подчеркнуть: введённый текст вакансии остался.
2. Загрузить корректный файл обратно → ошибка исчезла, конвейер работает.
3. **Текст-не-вакансия:** заменить вакансию рецептом блинов → «Сгенерировать» →
   отказ «Похоже, это не описание вакансии…», текст сохранился для правки.
4. Вернуть настоящую вакансию.

### Шаг 3. Работа с AI: ошибки и восстановление (SM-4)

1. Открыть PROMPTS.md — показать жёсткие правила против фабрикации.
2. Вариант А (если ошибка воспроизводится): неверный ключ/таймаут → показать
   сообщение ошибки и кнопку «Повторить» → восстановить ключ → «Повторить» → успех.
3. Вариант Б (галлюцинация): если модель в ответе добавила факт вне резюме —
   показать исходное резюме рядом с результатом и отметить расхождение;
   объяснить, что промпт это запрещает, и показать исправление повторным прогоном.
4. Ключевой тезис: система спроектирована так, что честность — архитектурное
   ограничение (промпт + JSON-схема + валидация), а не пожелание.

### Шаг 4. Проверка достоверности (SM-2)

Пройти по результатам демо с чеклистом:

- [ ] Каждый навык в адаптированном резюме присутствует в исходном резюме
- [ ] Даты/компании/образование совпадают с исходником
- [ ] Цифры и достижения не усилены по сравнению с исходником
- [ ] Сопроводительное письмо ссылается только на реальные факты

Отметить: проверка ручная сознательно — доверие строится на прозрачности промптов
(PROMPTS.md в репозитории), а не на «вере в чёрный ящик».

## Если что-то пошло не так на живой демонстрации

| Проблема | Действие |
|---|---|
| Прод недоступен | Переключиться на локальный `npm start` (резервный план) |
| Ошибка генерации | Показать «Повторить» — это часть сценария (Шаг 3), не сбой |
| Долгая генерация | Комментировать стадии трекера — это фича FR-9 |
