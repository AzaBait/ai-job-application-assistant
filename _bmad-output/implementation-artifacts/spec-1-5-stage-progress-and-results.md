## Intent

**Problem:** после нажатия «Сгенерировать» пользователь не видит стадии обработки, а результаты генерации нигде не отображаются — только текст «Документы готовы» без содержимого.

**Approach:** stage tracker (✓/●спиннер/○) поверх жизненного цикла generate-запроса + Зона 3 с двумя Document cards (развёрнутое превью первых строк). Фокус и автоскролл на результаты, повторный trust-line. Стадии — UX-лейблы (PRD FR-9 note), не серверный пайплайн.

## Boundaries & Constraints

**Always:**
- Tracker показывает стадии: анализ резюме → анализ вакансии → генерация результата; индикаторы ✓ готово / ● активно (спиннер) / ○ ожидание
- Спиннер дублируется текстом стадии; контейнер стадий `aria-live="polite"` (accessibility floor)
- Повторный запуск заблокирован до завершения (кнопка disabled в фазе generating — уже есть с 1.4, сохранить)
- Названия стадий — UX-лейблы поверх ОДНОГО реального запроса `/api/generate`: первые две стадии проходят быстро последовательно, третья активна всё время запроса; никакой имитации серверных стадий в API
- Document cards: заголовок документа, разворачиваемое превью первых строк (схлопнуто по умолчанию), полный текст доступен по развороту; скачивание НЕ реализуется здесь (Story 1.6) — кнопки не рендерятся
- Trust-line «Мы не добавляем факты, которых нет в вашем резюме» повторяется над карточками результатов
- По завершении генерации: автоскролл + клавиатурный фокус на заголовок Зоны 3
- Токены DESIGN.md: карточки `{colors.surface}`/`{rounded.card}`, спиннер `{colors.accent}`, ✓ `{colors.success}`

**Ask First:**
- Любой новый dependency (спиннер — CSS-анимация, без библиотек).

**Never:**
- Никаких кнопок скачивания PDF/DOCX и логики экспорта (Story 1.6)
- Никаких изменений сервера, контракта `/api/generate`, промптов, retry (Story 1.4 заморожена)
- Никаких изменений Dropzone/парсеров/VacancyInput/ToneSelect кроме чтения существующего состояния
- Никаких ошибочных веток генерации сверх уже существующего inline-error (Story 2.3)

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| GENERATING | Кнопка нажата | Tracker видим: стадия 1 ● → ✓, стадия 2 ● → ✓, стадия 3 ● активна до ответа; автоскролл к трекеру | N/A |
| SUCCESS | Ответ ok | Все стадии ✓; Зона 3: две cards c превью; фокус+скролл на заголовок Зоны 3; trust-line над ними | N/A |

- [ ] `client/src/components/DocumentCard.tsx` -- заголовок, кнопка разворота превью (первые ~8 строк), полный текст по развороту -- UX-DR7
- [ ] `App.tsx` -- Зона 3: две cards (Адаптированное резюме / Сопроводительное письмо), trust-line над ними, ref-заголовок Зоны 3 -- структура результатов
- [ ] Фокус/скролл: старт генерации → автоскролл к трекеру; успех → фокус+скролл на заголовок Зоны 3; сброс при regenerate/error -- управление вниманием
- [ ] Расширение harness (`scripts/check-results.mjs`) -- чистая логика прогрессии стадий и превью-обрезки против матрицы -- повторяемая проверка

**Acceptance Criteria:**
- Given нажата «Сгенерировать», when идёт обработка, then трекер показывает последовательное прохождение стадий, активная сопровождается спиннером и текстом, повторный клик невозможен
- Given успешный ответ, when рендерится Зона 3, then две карточки с корректными заголовками, превью схлопнуто, разворот показывает полный текст
- Given успех, then фокус установлен на заголовок Зоны 3, страница проскроллена к нему, trust-line виден над карточками
- Given ошибка генерации, then трекер не зависает в активной стадии, инлайн-ошибка видна
- Given повторный запуск, then трекер сбрасывается и проходит заново, старые карточки замещаются
- Given screen reader, then смены стадий озвучиваются через aria-live

## Design Notes

Прогрессия стадий без фейкового API: стадии 1–2 переводятся в ✓ таймерами (~600мс каждая) после старта запроса; стадия 3 активна с момента их завершения и до resolve/reject fetch. При ошибке — сброс всех стадий. Это честно соответствует PRD-заметке «UX-лейблы, не пайплайн».

Превью: первые 8 строк полного текста (`split('\n')`), разворот через `<details>` или кнопку + состояние — без библиотек.
