# Epic 1 Context: Отклик за минуты — рабочий end-to-end сценарий

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Пользователь проходит весь путь happy path: загружает валидное резюме PDF/DOCX, вставляет корректный текст вакансии, выбирает тональность, видит стадии генерации и скачивает оба документа (адаптированное резюме + сопроводительное письмо) в PDF или DOCX. После эпика продукт демонстрируем end-to-end на презентации — это ядро ценности двухдневного интенсива: отклик за минуты без выдуманных фактов. Ошибочные ветки входа в этот эпик не входят (Epic 2).

## Stories

- Story 1.1: Деплоируемый скелет продукта
- Story 1.2: Загрузка резюме и извлечение текста
- Story 1.3: Текст вакансии и выбор тональности
- Story 1.4: Генерация без фабрикации через BFF
- Story 1.5: Стадии процесса и просмотр результатов
- Story 1.6: Скачивание PDF и DOCX

## Requirements & Constraints

- Резюме принимается только в PDF или DOCX, ≤5 МБ; формат проверяется по magic-byte до парсинга.
- Текст вакансии: многострочный ввод с лимитом 10 000 символов (счёт в codepoints, не `.length`); ввод сверх лимита блокируется.
- Кнопка «Сгенерировать» активна только когда файл загружен И вакансия ≥200 символов И валидации пройдены; иначе disabled с подсказкой, чего не хватает.
- Тональность — фиксированный набор из 3 опций: Профессиональная (по умолчанию) / Дружелюбная / Уверенная.
- Никакой проверки совпадения языков резюме и вакансии — разноязычные пары проходят.
- Генерация выдаёт оба документа строго из фактов резюме: переформулирование, реструктуризация, релевантный опыт, ключевые слова вакансии — ни одного факта, отсутствующего в резюме (anti-fabrication).
- Пользователь видит стадии обработки (анализ → генерация) индикаторами ✓/●(спиннер)/○; повторный запуск заблокирован до завершения.
- Оба документа скачиваются в PDF и DOCX (4 варианта); экспорт сохраняет заголовки, списки, абзацы, разделители — планка MVP, пиксель-перфект не требуется.
- Продукт задеплоен по публичному URL уже после первой истории; каждая следующая история попадает в живое окружение.

## Technical Decisions

- **Один Node-процесс, один origin**: Hono BFF отдаёт собранную статику Vite SPA и `/api/*`; CORS не настраивается нигде (dev — Vite proxy). `GET /api/health` для проверки живости.
- **Ключ LLM только на сервере**: браузер никогда не говорит с провайдером напрямую; единственный путь генерации — `POST /api/generate`; `GEMINI_API_KEY` живёт в server env (локально `.env` gitignored, в проде — secret store).
- **Stateless**: извлечённые тексты, вакансия и результат живут только в памяти вкладки; каждый серверный запрос самодостаточен (все данные в теле запроса); ничего не сохраняется между запросами.
- **Парсинг и экспорт клиент-side**: `pdfjs-dist` (требует явного Vite worker `?worker` import + `wasmUrl` wiring day one) и `mammoth` — извлечение текста; `docx` (`Packer.toBlob`) и `pdf-lib` со встроенным Unicode/Noto Sans шрифтом (кириллица) — сборка скачиваемых файлов через Blob. Файл пользователя не покидает браузер.
- **Anti-fabrication defense in depth** (все слои обязательны): grounding-промпт с жёстким запретом фабрикации → провайдерский `responseSchema`, генерируемый из Zod-схемы в `shared/` → клиентская Zod-валидация ответа → один repair-retry (обрабатывает и невалидный вывод, и отказ провайдера принять схему); вторая неудача — ошибка пользователю. Промпты версионируются текстом в `server/src/prompts/*.ts`.
- **Лимиты на входе**: файл ≤5 МБ + magic-byte {PDF, DOCX} до парсинга; вакансия ≤10 000 символов; LLM ≤90 c (AbortController на клиенте + дублирующий таймаут на сервере).
- **Единая форма ошибки** `{code, message}` из закрытого реестра кодов в `shared/` (`FILE_TOO_LARGE`, `UNSUPPORTED_FORMAT`, `PARSE_FAILED`, `LLM_TIMEOUT`, `LLM_INVALID_OUTPUT`, `RATE_LIMITED`, …); message человекочитаемый; JSON-line логи без контента документов.
- **Env-only конфигурация**: `GEMINI_API_KEY`, `LLM_MODEL` (pinned alias), `PORT`; `.env.example` закоммичен.
- **Shared types**: Zod-схемы в `shared/` — единственный источник контрактов обоих эндпоинтов, envelope `{ok, data|error}`, enum'ов (тональность) и лимитов; import-only, дублирование формы или enum-литерала запрещено.
- **Стек**: Node 24 LTS, Vite 7, React 19, TypeScript strict, Hono, zod 4, Gemini Flash free tier.
- **Структура**: `client/` (components, flows, lib), `server/` (routes, llm, prompts), `shared/`. State — только локальный `useState`/reducer; глобальные сторы (Redux/Zustand) запрещены.

## UX & Interaction Patterns

- **Одностраничная IA, три зоны**: Header с trust-line «Ничего не выдумываем» → Зона 1 ввода (dropzone → textarea вакансии → тональность → кнопка «Сгенерировать») → Зона 2 прогресса → Зона 3 результатов.
- **Dropzone**: drag-and-drop + клик; после выбора — имя файла, размер, кнопка замены ×; мгновенная валидация формата/размера; состояния idle/dragover/error; доступна с клавиатуры (Enter/Space); после успешной загрузки фокус переходит на textarea.
- **Textarea вакансии**: счётчик символов; плейсхолдер с примером структуры вакансии; при превышении лимита счётчик цветом ошибки `{colors.error}`, кнопка disabled с подсказкой «Сократите текст вакансии».
- **Segmented control тональности**: под выбранной опцией одна строка описания.
- **Stage tracker**: охватывает только стадии после нажатия «Сгенерировать» (стадия загрузки живёт в dropzone, не в трекере); названия стадий — UX-лейблы поверх последовательных клиентских шагов, не отдельный серверный пайплайн; `aria-live="polite"`; автоскролл к трекеру при старте.
- **Success**: две Document cards (заголовок, разворачиваемое превью первых строк, кнопки «Скачать PDF»/«Скачать DOCX» — secondary outline); фокус и автоскролл на заголовок Зоны 3; trust-line повторяется над карточками («Мы не добавляем факты, которых нет в вашем резюме»).
- **Дизайн-токены DESIGN.md** подключаются как базовая тема уже в скелете: палитра (background #FFFFFF, surface #F8F9FA, border #DEE2E6, text #212529, accent #2563EB — только primary action и успех, error #DC2626 — только ошибки, success #16A34A), Inter/system-ui типографика, скругления 8px (кнопки/инпуты) и 12px (карточки), page-max-width 960px, spacing unit 4px. Без градиентов, иллюстраций и декоративных анимаций.
- **Responsive**: ≥1024px — две колонки (ввод слева, прогресс/результат справа); <1024px — одна колонка в порядке IA; segmented control горизонтальный. Touch-цели ≥44×44px.
- **Accessibility floor** (во всех историях): семантические `<label>`/`<button>`, aria-live для стадий, aria-describedby для ошибок, полная клавиатурная работа, спиннер дублируется текстом стадии, цвет ошибки не единственный маркер.

## Cross-Story Dependencies

- Story 1.1 — фундамент: все остальные истории строятся на его каркасе (SPA+BFF+health+env+дизайн-токены+деплой).
- Story 1.2 и 1.3 независимы друг от друга, обе питают Story 1.4 (generate-запрос требует resumeText + vacancyText + tone).
- Story 1.5 зависит от 1.4 (стадии трекера поверх вызова генерации) и от состояния формы 1.2–1.3 (кнопка активации).
- Story 1.6 зависит от 1.5 (Document cards со структурированными результатами).
- Ошибочные ветки (битый файл, не-вакансия, сбой LLM) сознательно отложены в Epic 2 — Epic 1 реализует только happy path, но архитектура ошибок `{code, message}` закладывается сразу.
