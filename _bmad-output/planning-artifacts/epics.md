# AI Job Application Assistant - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for AI Job Application Assistant, decomposing the requirements from the PRD, UX Design, and Architecture into implementable stories.

## Requirements Inventory

### Functional Requirements

- **FR-1:** Пользователь может загрузить Резюме в формате PDF или DOCX (лимит ~5 МБ; другие форматы отклоняются до обработки; при невозможности извлечь текст — понятное сообщение и возможность выбрать другой файл)
- **FR-2:** При невалидном файле пользователь видит человекочитаемое сообщение с указанием причины (формат/повреждён/текст не извлекается); после ошибки можно загрузить другой файл без перезапуска сценария
- **FR-3:** Пользователь может вставить произвольный текст Вакансии в текстовое поле (многострочный, лимит ~10 000 символов)
- **FR-4:** Сервис проверяет введённый текст на соответствие описанию вакансии перед Генерацией; не-вакансия/недостаточно информации → Генерация не запускается, понятное сообщение + просьба дать корректное описание; проверка без сохранения данных (LLM-вызов или эвристика — за архитектурой); ориентиры pass/fail: типичное описание с позицией/обязанностями проходит, «Lorem ipsum» или обрывок в несколько слов — нет
- **FR-5:** Отсутствует проверка «языки совпадают» как precondition; разноязычные пары резюме+вакансия не блокируются на уровне MVP; точный языковой scope — открытый вопрос
- **FR-6:** Пользователь может выбрать одну Тональность из фиксированного набора (3–4 варианта: профессиональная/дружелюбная/уверенная + значение по умолчанию)
- **FR-7:** Сервис генерирует Адаптированное резюме: переформулирование, реструктуризация, выделение релевантного опыта, ключевые слова Вакансии; без фактов, отсутствующих в Резюме
- **FR-8:** Сервис генерирует Сопроводительное письмо под Вакансию на основе фактов Резюме и выбранной Тональности; те же ограничения достоверности
- **FR-9:** Пользователь видит состояние процесса на каждой стадии: загрузка файла → анализ резюме → анализ вакансии → генерация результата → успех (+ отдельное состояние ошибки); прогресс/спиннер во время активных стадий; повторный запуск заблокирован до завершения; названия стадий — UX-лейблы, не пайплайн
- **FR-10:** При недоступности AI API или ошибке Генерации — понятное сообщение (без stack trace) с повтором попытки одной кнопкой; ввод не сбрасывается
- **FR-11:** Пользователь может скачать Адаптированное резюме и Сопроводительное письмо, каждое в PDF или DOCX (4 варианта скачивания); структура документа читаема в скачанном файле

### NonFunctional Requirements

- **NFR-1 (безопасность):** API-ключи AI-провайдера не хранятся и не используются на клиенте; механизм — решение архитектуры (нерушимое ограничение)
- **NFR-2 (UI):** Качественный адаптивный UI; критерии качества — зона bmad-ux (UX-спецификация)
- **NFR-3 (обязательные артефакты):** Deploy; README.md; PROMPTS.md с ключевыми промптами
- **NFR-4 (демонстрация):** Финальная презентация показывает процесс работы с AI, включая ошибки/галлюцинации модели и их исправление (SM-4)
- **NFR-5 (сроки):** Реализация и деплой в рамках двухдневного интенсива; приоритет — end-to-end сценарий
- **NFR-6 (стейтлесс):** Без регистрации/аккаунтов, без хранения пользовательских данных между сессиями
- **NFR-7 (метрики):** SM-1 e2e за минуты на презентации; SM-2 достоверность (ручная проверка демо-сессий); SM-3 устойчивость к некорректным входам; SM-C1 скорость генерации не ценой достоверности

### Additional Requirements

Из Architecture Spine (AD-1–AD-8):

- AD-1: Один Node-процесс, один origin: статика SPA + `/api/*`; CORS не настраивается (dev — Vite proxy)
- AD-2: Браузер никогда не говорит с LLM напрямую; только `POST /api/generate` через BFF; `GEMINI_API_KEY` в server env / secret store
- AD-3: Клиент оркестрирует конвейер; сервер обрабатывает каждый запрос самодостаточно; данные живут в памяти вкладки
- AD-4: Парсинг клиент-side (pdfjs-dist с Vite worker+wasm wiring, mammoth); экспорт client-side (docx, pdf-lib + встроенный Unicode/Noto Sans шрифт); файл не покидает браузер
- AD-5: Anti-fabrication defense in depth: grounding-промпт → responseSchema из Zod → Zod-валидация клиента → один repair-retry (обрабатывает и отказ провайдера принять схему); промпты версионируются в `server/src/prompts/`
- AD-6: Лимиты: файл ≤5 МБ + magic-byte {PDF, DOCX} до парсинга; вакансия ≤10 000 символов; LLM ≤90 c (AbortController + серверный таймаут); ретрай = новый POST
- AD-7: Единая форма ошибки `{code, message}`; закрытый реестр кодов в shared/: FILE_TOO_LARGE, UNSUPPORTED_FORMAT, PARSE_FAILED, VACANCY_INVALID, LLM_TIMEOUT, LLM_INVALID_OUTPUT, RATE_LIMITED; логи JSON-line без контента документов
- AD-8: Env-only конфигурация: GEMINI_API_KEY, LLM_MODEL (pinned alias), PORT; `.env.example` в репозитории
- Стек: Node 24 LTS, Vite 7, React 19, TypeScript strict, Hono BFF, zod 4, Gemini Flash free tier
- Shared types: Zod-схемы в `shared/` — единственный источник контрактов обоих эндпоинтов + envelope `{ok, data/error}` + enum'ы + лимиты (import-only, без дублирования)
- Символы считаются в codepoints через общую утилиту (не `.length`)
- PROMPTS.md генерируется из `server/src/prompts/`, вручную не правится
- State: только локальный useState/reducer, без глобальных сторов
- Структура проекта: client/ (components, flows, lib) + server/ (routes, llm, prompts) + shared/

### UX Design Requirements

Из EXPERIENCE.md + DESIGN.md:

- **UX-DR1:** Одностраничная IA из трёх зон: Header с trust-line «Ничего не выдумываем» → Зона 1 ввода (dropzone + textarea + тональность + кнопка) → Зона 2 прогресса → Зона 3 результатов (ASCII-каркас в EXPERIENCE.md §IA)
- **UX-DR2:** Dropzone: drag-and-drop + клик; после выбора имя файла, размер, кнопка замены ×; мгновенная валидация формата/размера; состояния idle/dragover/error по DESIGN.md токенам
- **UX-DR3:** Textarea вакансии со счётчиком символов; плейсхолдер с примером структуры вакансии; при превышении 10k — блокировка ввода, счётчик цветом ошибки `{colors.error}`, кнопка disabled с подсказкой «Сократите текст вакансии»
- **UX-DR4:** Segmented control тональности: Профессиональная (default) / Дружелюбная / Уверенная; одна строка описания под выбранной
- **UX-DR5:** Кнопка «Сгенерировать» активна только при: файл загружен И вакансия ≥200 симв. И валидации пройдены; disabled с подсказкой, чего не хватает
- **UX-DR6:** Stage tracker: ✓/●(спиннер)/○ по стадиям анализа-генерации (стадия загрузки живёт в dropzone, не в трекере); aria-live="polite"; скролл к трекеру при старте
- **UX-DR7:** Document card: заголовок, разворачиваемое превью первых строк, кнопки «Скачать PDF»/«Скачать DOCX»; inline-ошибка скачивания + кнопка «Повторить»; планка экспорта MVP — заголовки/списки/абзацы/разделители
- **UX-DR8:** Полный набор состояний: idle / uploading / analyzing×2+generating / success / file error / vacancy validation error / generation error (см. таблицу State Patterns EXPERIENCE.md); все ошибки inline у источника, без toast'ов и stack trace; ввод не сбрасывается при ошибке
- **UX-DR9:** Trust-line в header + повтор над результатами; копия «Мы не добавляем факты, которых нет в вашем резюме»
- **UX-DR10:** Accessibility floor: семантические label/button, aria-live для стадий, aria-describedby для ошибок, полная клавиатурная работа (dropzone Enter/Space), фокус после загрузки файла → textarea, после успеха — автоскролл+фокус на заголовок Зоны 3, touch-цели ≥44px
- **UX-DR11:** Responsive: ≥1024px — две колонки (ввод слева, прогресс/результат справа); <1024px — одна колонка в порядке IA; segmented control горизонтальный
- **UX-DR12:** Дизайн-токены DESIGN.md: палитра (accent #2563EB, error #DC2626 и др.), Inter/system-ui типографика, скругления 8/12px, page-max-width 960px; красный только для ошибок; без градиентов/декоративных анимаций
- **UX-DR13:** Voice & Tone микрокопий: простая поддерживающая, без жаргона; ошибки говорят что случилось + что делать; не обвиняют пользователя `[ASSUMPTION: язык интерфейса — открытый вопрос PRD §8]`

## Epic 1: Отклик за минуты — рабочий end-to-end сценарий

Пользователь проходит весь путь UJ-1 на happy path: загружает валидное резюме, вставляет корректную вакансию, выбирает тональность, видит стадии генерации и скачивает оба документа. После эпика продукт демонстрируем на презентации.
**FRs covered:** FR-1, FR-3, FR-5, FR-6, FR-7, FR-8, FR-9, FR-11
**UX-DR covered:** UX-DR1–7, UX-DR9, UX-DR11, UX-DR12 (accessibility floor — во всех историях)

### Story 1.1: Деплоируемый скелет продукта

As a **product owner**,
I want **задеплоенный каркас приложения (SPA + BFF на одном origin)**,
So that **каждая следующая история сразу попадает в живое окружение**.

**Acceptance Criteria:**

**Given** чистый репозиторий
**When** выполнен scaffold по структуре `client/ server/ shared/`
**Then** Node-процесс (Hono) отдаёт собранную статику Vite и отвечает на `GET /api/health`
**And** конфигурация только через env (`PORT`, `LLM_MODEL`, `GEMINI_API_KEY`), `.env.example` закоммичен, `.env` в `.gitignore` (AD-8)
**And** дизайн-токены DESIGN.md подключены как базовая тема (палитра, типографика Inter/system-ui, скругления)
**And** пустой одностраничный UI с header'ом и trust-line «Ничего не выдумываем» доступен по публичному URL деплоя (AD-1, UX-DR9, UX-DR12)

### Story 1.2: Загрузка резюме и извлечение текста

As a **соискатель**,
I want **загрузить резюме PDF/DOCX перетаскиванием или выбором файла**,
So that **сервис работает с моим реальным опытом без ручного копирования**.

**Acceptance Criteria:**

**Given** Зона 1 ввода
**When** я перетаскиваю или выбираю PDF/DOCX ≤5 МБ
**Then** dropzone показывает имя файла и размер, появляется кнопка замены × (UX-DR2)
**And** текст извлекается в браузере (pdfjs-dist c явным Vite worker/wasm wiring; mammoth для DOCX) — файл не отправляется на сервер (AD-4)
**And** формат проверяется по magic-byte до парсинга; валидный файл принимается (AD-6)
**And** извлечённый текст держится только в памяти вкладки (AD-3)
**And** после успешной загрузки клавиатурный фокус переходит на textarea вакансии; dropzone доступна с клавиатуры (Enter/Space)
*(Ошибочные ветки невалидного файла — Story 2.1)*

### Story 1.3: Текст вакансии и выбор тональности

As a **соискатель**,
I want **вставить текст вакансии и выбрать тон результата**,
So that **генерация учитывает конкретную вакансию и мой стиль**.

**Acceptance Criteria:**

**Given** Зона 1
**When** я вставляю многострочный текст
**Then** счётчик символов считает codepoints через общую утилиту `shared/`; при достижении 10 000 ввод сверх лимита блокируется, счётчик становится `{colors.error}`, кнопка генерации disabled с подсказкой «Сократите текст вакансии» (FR-3, UX-DR3)
**And** segmented control: Профессиональная (default) / Дружелюбная / Уверенная, одна строка описания под выбранной опцией (FR-6, UX-DR4)
**And** кнопка «Сгенерировать» активна только когда файл загружен И вакансия ≥200 символов; иначе disabled с подсказкой, чего не хватает (UX-DR5)
**And** отсутствует проверка совпадения языка резюме и вакансии — разноязычные пары проходят (FR-5)

### Story 1.4: Генерация без фабрикации через BFF

As a **соискатель**,
I want **получить адаптированное резюме и сопроводительное письмо строго из фактов моего резюме**,
So that **отклик релевантен вакансии и не содержит выдуманного**.

**Acceptance Criteria:**

**Given** заполненная форма
**When** клиент вызывает `POST /api/generate` с `{resumeText, vacancyText, tone}`
**Then** сервер вызывает LLM (ключ из server env; браузер никогда не обращается к провайдеру — AD-2) с системным промптом жёсткого запрета фабрикации и grounding-контекстом «только текст резюме + вакансии из запроса» (AD-5)
**And** `responseSchema` генерируется из Zod-схемы в `shared/`; невалидный вывод ИЛИ отказ провайдера принять схему → один repair-retry; вторая неудача → ошибка `{code, message}` из закрытого реестра (AD-5, AD-7)
**And** таймаут вызова 90 c: AbortController на клиенте и дублирующий таймаут на сервере (AD-6)
**And** ответ содержит оба документа в структурированной форме; ничего не сохраняется между запросами (AD-3)
**And** промпт версионируется в `server/src/prompts/*.ts` (FR-7, FR-8)

### Story 1.5: Стадии процесса и просмотр результатов

As a **соискатель**,
I want **видеть, на какой стадии обработка, и развернуть результат перед скачиванием**,
So that **я понимаю, что сервис работает, и доверяю результату**.

**Acceptance Criteria:**

**Given** нажата «Сгенерировать»
**When** идёт обработка
**Then** stage tracker показывает стадии анализа-генерации индикаторами ✓/●(спиннер)/○ с aria-live="polite"; повторный запуск заблокирован до завершения; страница автоскроллится к трекеру (FR-9, UX-DR6)
**And** названия стадий — UX-лейблы поверх последовательных шагов клиента (анализ → генерация), не отдельный серверный пайплайн
**And** по завершении — Зона 3: две Document cards (Адаптированное резюме, Сопроводительное письмо) с разворачиваемым превью первых строк (UX-DR7)
**And** клавиатурный фокус и автоскролл переходят на заголовок Зоны 3; trust-line повторяется над карточками (UX-DR9)
**And** состояние success соответствует State Patterns EXPERIENCE.md

### Story 1.6: Скачивание PDF и DOCX

As a **соискатель**,
I want **скачать каждый документ в PDF или DOCX**,
So that **я могу приложить файлы к отклику на площадке работодателя**.

**Acceptance Criteria:**

**Given** Зона 3 с результатами
**When** я нажимаю «Скачать PDF» или «Скачать DOCX» на любой из двух карточек
**Then** файл собирается в браузере (docx — Packer.toBlob; pdf-lib со встроенным Noto Sans для кириллицы) и скачивается через Blob (FR-11, AD-4)
**And** все 4 варианта скачивания работают; экспорт сохраняет заголовки, списки, абзацы и разделители — планка MVP (UX-DR7)
**And** layout адаптивен: ≥1024px две колонки (ввод слева, прогресс/результат справа), <1024px одна колонка в порядке IA (UX-DR11)
**And** touch-цели ≥44×44px

## Epic 2: Устойчивость на границах входа

Все ошибочные ветки становятся управляемым UX: битый файл, не-вакансия, сбой LLM — каждый случай получает понятное сообщение и путь восстановления без потери ввода. Готовность к показу «процесс работы с AI, включая ошибки и их исправление» (SM-4).
**FRs covered:** FR-2, FR-4, FR-10
**NFRs covered:** NFR-3 (README/PROMPTS/deploy), NFR-4 (демонстрация AI-процесса)
**UX-DR covered:** UX-DR8, UX-DR13

### Story 2.1: Понятные ошибки невалидного файла

As a **соискатель**,
I want **при проблеме с файлом видеть понятное сообщение и сразу заменить файл**,
So that **случайная опечатка в файле не заставляет начинать всё заново**.

**Acceptance Criteria:**

**Given** Story 1.2 работает
**When** я загружаю файл неподдерживаемого формата / повреждённый / без извлекаемого текста
**Then** inline-ошибка в dropzone называет причину и поддерживаемые форматы: «Этот формат не поддерживается. Загрузите резюме в PDF или DOCX (до 5 МБ)» / «Не удалось прочитать файл. Похоже, он повреждён — попробуйте другой PDF или DOCX» (FR-2, UX-DR8)
**And** ошибка связана с dropzone через `aria-describedby`; введённый текст вакансии и тональность не сбрасываются
**And** замена файла доступна немедленно; после успешной замены ошибка исчезает, конвейер продолжает работать
**And** коды ошибок из закрытого реестра: `UNSUPPORTED_FORMAT`, `FILE_TOO_LARGE`, `PARSE_FAILED` (AD-7)

### Story 2.2: Валидация вакансии с отказом

As a **соискатель**,
I want **сервис честно отказался генерировать по тексту, который не является вакансией**,
So that **я не получаю сомнительный результат и понимаю, что исправить**.

**Acceptance Criteria:**

**Given** заполненная форма
**When** я нажимаю «Сгенерировать»
**Then** перед генерацией выполняется проверка текста (`POST /api/validate-vacancy`, контракт в `shared/`); стадия «анализ вакансии» в трекере соответствует этому шагу (FR-4)
**And** для типичного описания с позицией/обязанностями/требованиями проверка проходит, генерация продолжается (pass-ориентир PRD)
**And** для «Lorem ipsum», рецепта или обрывка в несколько слов генерация не запускается; inline-ошибка под textarea: «Похоже, это не описание вакансии. Вставьте текст вакансии с требованиями — и мы всё сделаем» (fail-ориентир, UX-DR13)
**And** введённый текст сохраняется для правки; повторный запуск возможен после исправления без перезагрузки страницы
**And** код ошибки `VACANCY_INVALID` из реестра; ничего не сохраняется на сервере (AD-3)

### Story 2.3: Ошибки генерации и ретрай одной кнопкой

As a **соискатель**,
I want **при сбое AI получить понятное сообщение и повторить попытку одним нажатием**,
So that **временный сбой не стоит мне всего сценария**.

**Acceptance Criteria:**

**Given** идёт или завершилась генерация
**When** AI API недоступен / таймаут 90 c / ответ невалиден дважды / превышен лимит провайдера
**Then** пользователь видит понятное сообщение в зоне прогресса («Произошла временная ошибка. Попробуйте ещё раз») — без stack trace и технических деталей (FR-10)
**And** кнопка «Повторить» запускает новый POST `/api/generate`; весь ввод сохранён
**And** маппинг кодов `LLM_TIMEOUT`, `LLM_INVALID_OUTPUT`, `RATE_LIMITED` → человекочитаемые сообщения на языке UI (AD-7)
**And** состояние generation error соответствует State Patterns EXPERIENCE.md; stage tracker переходит в ошибочное состояние, не зависает

### Story 2.4: Артефакты интенсива и демо-пас

As a **product owner**,

So that **проект сдан по чеклисту ТЗ и презентация показывает работу с AI, включая ошибки и их исправление**.

**Acceptance Criteria:**

**Given** все истории Epic 1–2 выполнены
**When** открываю репозиторий и прод-URL
