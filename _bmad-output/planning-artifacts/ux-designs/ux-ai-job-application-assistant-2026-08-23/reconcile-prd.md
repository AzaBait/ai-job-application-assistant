### Все шесть состояний FR-9

PRD: загрузка файла → анализ резюме → анализ вакансии → генерация → успех + отдельное состояние ошибки генерации.

Спек: Uploading file ✅ · Analyzing resume ✅ · Analyzing vacancy ✅ · Generating ✅ · Success ✅ · Generation error ✅ (строка «Analyzing resume / vacancy / generating» покрывает все три стадии). Дополнительно есть Idle и Vacancy validation error — согласовано с FR-4, не противоречит FR-9.

### Ключевые проверки

- **Тональность с дефолтом:** да — «Профессиональная (по умолчанию)», сценарий работает без обязательного выбора (FR-6).
- **4 варианта скачивания:** да — каждая карточка: «Скачать PDF» + «Скачать DOCX».
- **Принцип «не выдумываем» видим:** да — trust-line в header + повтор над карточками результата («Мы не добавляем факты…»); KF-1 проговаривает его до первого действия.
- **Non-Goals не нарушены:** нет аккаунтов, истории, diff-просмотра, интеграций; KF-1 явно завершается «сайт ничего не сохранил». Кнопка «Начать заново» — только сброс формы в памяти клиента, хранения нет.

## Гэпы

### GAP-1 · Medium · Планка качества экспорта (FR-11) не определена
PRD FR-11 прямо делегирует UX решение: «какой уровень структуры скачанного файла (заголовки, списки, разделители) приемлем для MVP». Ни EXPERIENCE.md, ни DESIGN.md этот вопрос не упоминают — делегированная ответственность осталась ничьей. Нужно одно предложение: например, «в скачанном файле читаемы заголовки разделов и маркированные списки; типографика не гарантируется». Блокирует: приёмку FR-11 на демо.

### GAP-2 · Low · Кнопка «Начать заново» — изобретённый контрол без тега
В состоянии Success появляется «Начать заново» с confirm-подсказкой — этого контрола нет в PRD (FR-1–11) и он не помечен `[OPTIONAL]`/`[FUTURE]`, хотя остальная дисциплина тегов выдержана строго. Функционально безвреден (не нарушает non-goals), но по формальному критерию «ничего изобретённого за пределами тегов» — либо добавить тег `[OPTIONAL]`, либо убрать.

### GAP-3 · Low · Копия отказа по неподдерживаемому формату не задана
FR-1 требует, чтобы при отклонении файла другого формата сообщение называло поддерживаемые форматы; FR-2 — чтобы называлась причина. В §Voice and Tone дан пример копии только для повреждённого файла («Не удалось прочитать файл…»). Для случая «неверный формат» копию стоит зафиксировать (например: «Это не PDF или DOCX. Загрузите резюме в одном из этих форматов») — иначе реализация придумает её сама.

## Вердикт

Покрытие полное по всем FR-1–FR-11 с UI-измерением; шести состояний FR-9 достаточно; тональность с дефолтом, 4 варианта скачивания, trust-line и адаптивность подтверждены; противоречий с Non-Goals нет. Один средний гэп (GAP-1) желательно закрыть до передачи в архитектуру/сторис; GAP-2, GAP-3 — косметика.
