# EXPERIENCE.md

## Foundation

- **Форм-фактор:** адаптивное веб-приложение (desktop-first по макету, полностью работоспособно на mobile). Без навигации, без меню — одностраничный линейный инструмент.
- **UI-система:** не фиксируется на уровне PRD; визуальная идентичность — `DESIGN.md`. Поведенческие паттерны ниже самодостаточны и реализуемы на любом стеке.
- **Принцип:** один экран = один этап сценария UJ-1 из PRD. Ноль лишних шагов: от открытия сайта до скачивания — только обязательные действия пользователя.

## Information Architecture

Одна страница, три вертикальные зоны (на mobile — одна колонка, зоны следуют друг за другом):

```
┌─────────────────────────────────────┐
│ Header: название + trust-line       │
│ «Ничего не выдумываем»              │
├─────────────────────────────────────┤
│ ЗОНА 1 · ВВОД                       │
│  1. Загрузка резюме (dropzone)      │
│  2. Текст вакансии (textarea)       │
│  3. Тональность (segmented control) │
│  [Кнопка «Сгенерировать»]           │
├─────────────────────────────────────┤
│ ЗОНА 2 · ПРОГРЕСС                   │
│  Стадии FR-9 + спиннер              │
├─────────────────────────────────────┤
│ ЗОНА 3 · РЕЗУЛЬТАТ                  │
│  [Карточка: Адаптированное резюме]  │
│  [Карточка: Сопроводительное письмо]│
│  каждая: превью + PDF/DOCX скачать  │
└─────────────────────────────────────┘
```

- **Поверхности и потребности (surface closure):** каждая потребность PRD имеет зону; каждая зона обслуживает шаг UJ-1. Отдельных экранов нет — прогресс и результат появляются под формой ввода после запуска.
- **Trust-line** в header и повтор в шапке Зоны 3: «Мы не добавляем факты, которых нет в вашем резюме» — постоянное объяснение принципа достоверности (FR-7/8), без отдельной страницы `[FUTURE: страница «Как это работает»]`.

## Voice and Tone

- Микрокопия — простая, поддерживающая, без жаргона. Обращение на «вы» `[ASSUMPTION: язык интерфейса — открытый вопрос PRD §8; копии ниже даны по-русски как референс]`.
- Ошибки говорят **что случилось** и **что делать**: «Не удалось прочитать файл. Похоже, он повреждён — попробуйте другой PDF или DOCX», а не «Error: parse failed».
- Никогда не обвиняем пользователя: «Похоже, это не описание вакансии. Вставьте текст вакансии с требованиями — и мы всё сделаем».

## Component Patterns

| Компонент | Поведение |
|---|---|
| **Dropzone резюме** | Drag-and-drop + клик для выбора файла. После выбора: имя файла, размер, кнопка замены ×. Формат/размер валидируются мгновенно (PDF/DOCX, ~5 МБ — PRD FR-1). |
| **Textarea вакансии** | Счётчик символов (лимит 10 000 — FR-3). Плейсхолдер с примером структуры вакансии. |
| **Segmented control тональности** | 3 опции: Профессиональная (по умолчанию) / Дружелюбная / Уверенная. Под выбранной — одна строка описания. |
| **Кнопка «Сгенерировать»** | Активна только когда файл загружен И текст вакансии ≥ минимальной длины `[ASSUMPTION: ~200 символов]` И валидация пройдена. Иначе disabled с подсказкой, чего не хватает. |
| **Stage tracker** | Вертикальный список стадий генерации с индикаторами: ✓ готово / ● активно (спиннер) / ○ ожидание. Стадия «загрузка файла» в трекере не отображается — она живёт в dropzone; трекер охватывает стадии после нажатия «Сгенерировать». |
| **Document card** | Заголовок документа, свёрнутое текстовое превью (первые строки, разворачивается), две кнопки: «Скачать PDF», «Скачать DOCX» (FR-11). Планка экспорта для MVP: сохраняются заголовки, списки, абзацы и разделители; пиксель-перфект вёрстка не гарантируется. Ошибка скачивания — inline-сообщение в карточке и кнопка «Повторить» `[OPTIONAL: системный toast]`. |
| **Кнопка «Начать заново»** | Сбрасывает форму к idle `[OPTIONAL]` с запросом подтверждения. |

## State Patterns

Полный набор состояний процесса (PRD FR-9/10):

| Состояние | UI |
|---|---|
| Idle | Зона 1 активна; зоны 2–3 отсутствуют. |
| Uploading file | Прогресс в dropzone; поля вакансии уже доступны. |
| Analyzing resume / vacancy / generating | Stage tracker показывает текущую стадию; кнопка генерации скрыта; повторный запуск невозможен (PRD FR-9); скролл к трекеру. |
| Success | Зона 3 с двумя Document cards; trust-line повторяется над ними; клавиатурный фокус и автоскролл — на заголовок Зоны 3; кнопка «Начать заново» `[OPTIONAL]`. |
| File error | Inline-ошибка в dropzone с указанием причины и поддерживаемых форматов: «Этот формат не поддерживается. Загрузите резюме в PDF или DOCX (до 5 МБ)». Форма сохранена, можно сразу выбрать другой файл (FR-2). |
| Vacancy validation error | Inline-ошибка под textarea с просьбой вставить корректную вакансию (FR-4); введённый текст сохраняется для правки. |
| Generation error | Сообщение в зоне 2: понятный текст + кнопка «Повторить» одной кнопкой (FR-10); ввод не сбрасывается. |

- Все ошибки — inline рядом с источником проблемы; toast-ы не используются.
- Никаких stack trace и технических кодов (PRD FR-10).
- Превышение лимита вакансии (10 000 символов, FR-3): ввод сверх лимита блокируется, счётчик становится ошибочным цветом `{colors.error}`, кнопка «Сгенерировать» disabled с подсказкой «Сократите текст вакансии».

## Interaction Primitives

- Один primary action на зону; фокус клавиатуры следует логике сверху вниз.
- После успешной загрузки файла фокус переходит на textarea.
- После завершения генерации — автоскролл к Зоне 3.
- Замена файла или правка вакансии после генерации помечает результат устаревшим (`[OPTIONAL: плашка «Ввод изменился — сгенерируйте снова»]`) `[FUTURE: авто-регенерация]`.

## Accessibility Floor

- Семантические элементы: `<label>` у каждого поля, кнопки — `<button>`, стадии — живой регион (`aria-live="polite"`).
- Спиннер дублируется текстом стадии (не только анимация).
- Ошибки связываются с полями через `aria-describedby`; цвет ошибки не единственный маркер — всегда текст.
- Полная работа с клавиатуры: dropzone доступна через Enter/Space, порядок табуляции линейный.
- Контраст и размеры — по `DESIGN.md` токенам `{colors.text}`, `{colors.text-muted}` и др.

## Key Flows

- **KF-1. Мария получает отклик за минуты** *(реализует UJ-1, SM-1)*
  Мария открывает сайт. Trust-line объясняет принцип честности ещё до первого действия. Она перетаскивает PDF резюме в dropzone — файл принят, имя видно, фокус на textarea. Вставляет вакансию, счётчик показывает запас лимита. Тональность оставляет «Профессиональная». Кнопка активна — нажимает. Stage tracker ведёт её по стадиям анализа и генерации. Автоскролл к двум карточкам результатов: разворачивает превью письма, устраивает тон — скачивает письмо DOCX и резюме PDF. **Climax:** оба файла на диске, сайт ничего не сохранил. **Развязка:** закрывает вкладку. **Edge case:** если бы файл был битым — inline-ошибка в dropzone, второй файл выбирается без потери введённого текста вакансии.

## Responsive & Platform

- **Desktop (≥1024px):** зоны 1 и 2/3 могут располагаться в две колонки (ввод слева, прогресс/результат справа) `[ASSUMPTION: одноколоночный поток тоже допустим — решает дев по месту]`.
- **Tablet/Mobile (<1024px):** одна колонка в порядке IA; segmented control тональности остаётся горизонтальным, при нехватке ширины — со скроллом; document cards — full-width, кнопки скачивания в ряд.
- Touch-цели ≥44×44px; никаких hover-only подсказок.
- `[FUTURE]: PWA, офлайн-индикация, тёмная тема.`

## Открытые вопросы UX

1. Язык интерфейса (открытый вопрос PRD §8) — блокирует финальные копии, не блокирует структуру.
2. Минимальная длина вакансии для активации кнопки — `~200 символов`, подтвердится тестами на демо-входах.
